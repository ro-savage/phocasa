## Deviations from the task file

1. **`SplitMix64` was missing.** `assets/PerformanceBenchmarks.swift` calls `SplitMix64(state: 42)`, but no such type
   exists in the repo, so the file didn't compile as shipped. I added a standard SplitMix64
   `RandomNumberGenerator` (file-private, at the bottom of the benchmark file). Seeding is deterministic: both runs
   report identical `rated3`, `tagPeople0` and `searchMatches` counts. They may not be the exact counts the spec's run
   had, but the timings match the spec closely.
2. **One `Task.sleep` kept.** I removed both 2 s "let the host app finish launching" delays, as asked. The 500 ms
   sleep after the `setRating` benchmarks stays: it isn't a launch delay. It lets the detached metadata writes that
   `setRating` starts drain before the in-memory baselines in section 6 are measured.
3. **Extra probes.** Besides the two probes the task asked for, I probed a file in a new *nested* folder, because wave
   1 creates `Library/`, `Views/Detail/`, `Services/Thumbnail*` and `Editing/`. I also checked that Finder
   `.DS_Store` files inside the synchronized folder don't end up in the bundle.
4. **`findRAW()` details.** Its body now reads `$IMAGEBENCH_RAW` and returns nil unless the path is a readable
   regular file. I kept the `SF_DATALESS` check, so a cloud-only file is never read (reading it would trigger a
   download). I dropped the `st_size > 1 MB` filter, which only existed to sift `mdfind` results. There are two skip
   messages: "`IMAGEBENCH_RAW` isn't set" and "… is not a local, readable regular file". Only the unset branch was run
   (see "Couldn't verify").
5. **imagebench header comment.** I updated the build and run lines and added data-dir and RAW notes. This is a
   comment-only change.
6. **`git rm --cached .DS_Store Phocasa/.DS_Store` was a no-op.** Neither file was ever tracked; they're untracked in
   the main checkout. The new `.gitignore` covers them.
7. **imagebench data doesn't quite match the spec.**
   - With the default arguments, `gen` writes a **15.0 MB** master (15,729,846 B). The spec says 12.6 MB.
   - `gen` + `copies` use **~2.9 GB**, not ~2.5 GB. The tool's README says "about 3 GB".
   - JPEG decodes on this data are about 15–20% slower than the spec's table: `thumb` gives ~93 ms software and ~55 ms
     hardware, against the spec's ~82 / ~46 ms.
   - `gen`'s own verify line prints `embedded thumbnail (IfAbsent, no max, no transform): 6000x4000`. The thumbnail
     *is* embedded: there's a second SOI inside the 5.4 KB APP1 segment, and `thumb` returns 106×160 for `IfAbsent`.
     ImageIO just doesn't return it when no max size is given.
   - I documented all of this in `Tools/imagebench/README.md` instead of changing more Swift (the task allows only the
     `findRAW` change).
   - This doesn't affect `orient`. For timing comparisons, main and branch must use data from the same `gen`, which
     the coordinator's protocol already does.
8. **Test count wording.** xcodebuild now reports `Executed 125 tests, with 3 tests skipped`. Where the plan and task
   files say "122 tests", read it as "125 executed, 3 skipped, 0 failures".

## Follow-ups

- **The benchmark harness is a consumer of view-model APIs.** It calls:
  - `setModelContext`, `loadExistingData`, `refreshAvailability`
  - `applyFilter(.rated/.tag/.all)`, `applyCurrentFilter`, `toggleSortOrder`, `sortNewestFirst`, `searchText`
  - `setRating(_:for:)`, `selectedPhotos`, `selectedPhotosList`
  - `allPhotos`, `photos`, `allTags`, `currentLibrary`
  - `rescanCurrentLibrary`, `isScanning`, `scanProgress`, `findOrCreateTag(name:category:in:)`
  - `FolderScanner().scan(folderURL:)`, `MetadataService.shared.readMetadata(from:)` / `writeMetadata(rating:keywords:toImageAt:)`
  - `#Predicate { !$0.isDeleted }`

  Any task that renames or removes one of these must update the harness in the same branch. Task 31 renames
  `isDeleted`. Task 10 may retire `loadExistingData`.
- **The scan timings depend on `isScanning` being set synchronously.** `waitForScan` relies on
  `rescanCurrentLibrary()` setting `isScanning = true` before it returns. If task 20's off-main scan sets it later,
  benchmarks 7x, FIRST and SECOND will silently measure ~0 ms. Task 20 should keep the flag synchronous, or give the
  harness a proper way to await the scan.
- **imagebench mirrors the app's image code by hand.** When tasks 11, 12 and 13 change the app's decode or render
  options, the "(app)" rows in imagebench keep measuring the old path unless someone updates them.
- **Possible small fix:** pass a max pixel size in `gen`'s verify line, so it prints the real 106×160 embedded
  thumbnail.
