## Layout for wave 3B

under 400 lines (see deviations).

### Task 33: capture-date sort

  | Member | What it does |
  |---|---|

## Deviations from the task file, and why

1. **Steps 2 and 3 landed in one commit, followed by the test moves.** `SelectionModel` reads positions from
   `LibraryStore` (`index(of:)`, `shownIDs`, `photos`), so the library had to exist first. The commits are:
   - `03433cd`: the split;
   - `f1e256a`: the test moves;
   - `fd70677`: new `LibrarySort` and scan tests.
2. **Two extra extension files, `+ListEditing` and `+Filtering`.**
   - The task file's `+Mutations` (rating, tags, bin, relocate, grid patching) would have been about 480 lines.
   - Grid patching stays in `LibraryStore.swift`, so `photos` can stay `private(set)`: that is what makes an outside
     write fail to compile (integration fix `78ebe1b`).
   - The relocation helpers moved to `+ListEditing`; filters, search, the sort toggle and the tag lists to `+Filtering`.
3. **Some setters are now `internal`.** Stored properties that extension files write can't be `private(set)` across
   files: `tagsByCategory`, `uncategorizedTags` and the in-memory state. The type's doc comment says so. The counts
   and `photos` are still `private(set)`.
4. **What stays on the view model.**
   - Flows that also change the selection stay there, with the same signatures: `deleteSelected`, `deletePhoto`,
     `restoreFromBin`, `restoreSelected`, `confirmPermanentDelete`, `emptyBin`, `setRatingForSelection`,
     `setRatingForSelectionOrCurrent`, `addTagToSelection`, `toggleTag`, `contextMenuTagState`,
     `openTagEditorForContextMenu`, `applyPresetToSelection` and `revertEditsForPhoto`.
   - The library gained batch forms instead: `setRating(_:for: [PhotoAsset])`, `addTag(name:category:to: [PhotoAsset])`
     and `removeTag(_:from: [PhotoAsset])`.
   - `navigateGrid` moved to `SelectionModel` and takes `columns:`, since `gridColumns` is a view-model UI flag.
     `ContentView` passes it.
5. **Views read `library`/`selection` directly, with no forwarding properties.** The only forwarder is
   `loadExistingData()`, which is required. `SidebarView` takes the library itself.
6. **`sortNewestFirst` is read-only**, computed from `library.sort`. The oracle sets `library.sort`.
7. **The trashing delete entry points return their task.** `deleteSelected()`, `deletePhoto(_:)` and
   `confirmPermanentDelete()` now return `Task<Void, Never>?` (discardable), so tests can await them.
   - Moves to and from the bin stay synchronous and return nil.
   - The store changes after the files are in the Trash, as the task says. Until then the photos stay on screen.
   - A photo whose delete is still running can't be deleted twice (`photosBeingDeleted`).
   - `FileTrasher` checks that each file exists before trashing it. The old code checked only for the sidecar; the
     result is the same.
8. **Pausing the hidden grid is part of each cell's task identity.** Opening the detail view therefore also cancels
   the grid loads in flight, which frees the decoder for the detail view. Closing restarts them, served from the memory
   cache.
9. **`MainContentView` is its own file.** The task said `ContentView.mainContent`; a separate type lets tests host
   the window's real content.
10. **Test instrumentation in app code:**
    - `ContentView.init(viewModel:)`: the app passes nothing;
    - three `static` counters: `ContentView.bodyEvaluations`, `StatusBarView.bodyEvaluations` and
      `PhotoGridItemView.thumbnailLoadsStarted`, the last one where the task file said to put it.
11. **Beyond the task file:**
    - `LoadingState`/`ScanState`, for wave-3B isolation;
    - `waitForScans()`, the after-launch hook the coordinator asked for;
    - `LibraryStore.tagIDs(of:)`, facts-based;
    - the unused `showDeleteConfirmation` flag is removed.
12. **"Index-based selection" for the context menu.** `selectedPhotosList` was already index-based since task 10. What
    the menu still did was, for every tag, rebuild the selection list and read every selected photo's `tags`. Now it
    computes one set of checked tags per menu from the facts. `toggleTag`'s "all have it" check uses the same set.

## Follow-ups

- **Launch still blocks the main actor for about 345 ms at 10k** (`loadExistingData`). Task 32.
- **Deletes that trash files reload the whole library afterwards** (about 320 ms at 10k), as before. This is now after
  the trashing, off the critical path. An in-memory removal like `relocate` would make it milliseconds.
- **Quit waits for metadata writes only.**
  - A running trash batch is cut off: its store update doesn't happen, so its rows stay until the next scan marks them
    missing.
  - An open edit session isn't saved on quit. That is existing behaviour.
- **Duplicate rows** already in a user's store are tolerated but not merged (from `results/20.md`).
- **Recommendations only, with their evidence:**
  - **Replacing `LazyVGrid`** (`results/11.md`): cell creation costs about 1 ms per cell and 31–40 ms per page of
    scrolling, the same at 2k and 10k. Revisit `NSCollectionView` only if the real app drops frames.
  - **A Metal preview view** (`results/13.md`, `22.md`): the main-thread first draw of a full-resolution edit is 26–36 ms
    in the CPU-draw proxy (34.2 ms here for 24 MP). `MTKView` + `CIRenderDestination` would remove it.
  - **Colour management** (`results/13.md`): the pipeline uses a Device RGB working space and output tag. Changing it
    changes output, so it's a deliberate product decision.
